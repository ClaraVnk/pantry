Ce que fait Chaudron

Chaudron tient l'inventaire de ce qu'un foyer a réellement en stock — placards, réfrigérateur, congélateur — et s'en sert pour proposer des recettes. Le tout tourne sur votre serveur, avec le modèle de langage de votre choix.

Suivi du stock
Ce que vous avez, où c'est rangé, et quand ça périme. La date limite de consommation et la date de durabilité minimale sont deux choses différentes : les confondre, c'est soit s'alarmer pour des pâtes sèches, soit se taire sur de la viande hachée.
Lecture de codes-barres
Le décodage se fait dans le navigateur : le serveur ne reçoit jamais un flux vidéo, seulement treize caractères. Les produits sont résolus via Open Food Facts.
Suggestions de recettes
Elles partent du stock réellement présent. La disponibilité d'un ingrédient est recalculée sur votre inventaire, jamais reprise du modèle sur parole.
Votre modèle, votre clé
Anthropic, OpenAI, Gemini, Mistral, ou un Ollama local. Il n'existe aucun mode dans lequel le projet paierait l'inférence à votre place — et donc aucun endroit où vos habitudes alimentaires transiteraient par un service tiers que vous ne choisissez pas.
Rappels de péremption sur le téléphone
Une collection CalDAV de tâches, en lecture seule. Parce qu'elle n'annonce que des tâches, un iPhone la classe dans Rappels et non dans Calendrier.

Vos données ne partent pas

Un inventaire de cuisine dit beaucoup : le budget d'un foyer, ses allergies, ses horaires, le nombre de personnes qui y vivent. Chaudron traite cela comme des données personnelles, pas comme du contenu.

Il n'y a pas de cloud Chaudron, pas de compte Chaudron, pas de clé d'API Chaudron. L'instance que vous installez ne parle à personne d'autre que vous et au fournisseur de modèle que vous avez vous-même configuré. Les écrans de l'application ne sont pas indexables : cette page d'accueil est la seule que les moteurs de recherche voient.

Auto-héberger Chaudron

Le projet est jeune, et pas encore exposable sur Internet. L'authentification n'est pas terminée : installez Chaudron sur un réseau privé, ou derrière votre propre authentification, en attendant.

Il vous faut uv, Podman et Node.js 22 ou plus récent. 

git clone https://github.com/ClaraVnk/chaudron.git
cd chaudron
cp .env.example .env

podman run -d --name chaudron-db \
  -e POSTGRES_PASSWORD="$(openssl rand -hex 16)" \
  -v chaudron-db-data:/var/lib/postgresql/data:Z \
  -p 127.0.0.1:5432:5432 docker.io/library/postgres:16

cd backend && uv sync && uv run alembic upgrade head
uv run uvicorn chaudron.api.main:app

Le déploiement visé est PostgreSQL, Podman en rootless et des unités systemd quadlet, sur un petit VPS ou un serveur domestique. La marche à suivre complète est dans le dépôt.

Libre, et qui le reste

Chaudron est publié sous licence AGPL-3.0. Le choix de l'AGPL plutôt que d'une licence permissive est délibéré : quiconque fait tourner une version modifiée comme service doit en publier le code. Un projet dont l'argument est « vous gardez la main sur vos données » ne peut pas laisser quelqu'un d'autre en faire un service fermé.

Le code, les tickets et les contributions sont sur github.com/ClaraVnk/chaudron.
